# AI销管王内部试点 PRD

版本：v0.1  
状态：讨论稿  
日期：2026-07-14  
适用范围：公司内部试点开发  

## 1. 产品概览

### 1.1 产品定位

AI销管王不是传统重 CRM，也不是单独的 AI 报告工具，而是一套围绕“销售专用手机数据 + 渠道订单数据 + 客户资产 + AI分析 + 销售执行 + 管理干预”的销售增长系统。

系统核心目标是：让销售把有限精力投入到最可能成交、最值得维护、最需要及时干预的客户上，从而提升成单率、复购率、转介绍和整体营收。

### 1.2 核心问题

当前销售过程存在几个核心问题：

- 客户来源分散：抖店、视频号、小鹅通、百度、代发、其他渠道订单和线索格式不统一。
- 客户身份难匹配：有些订单没有真实手机号，可能只有微信号、昵称、平台ID、收货人或地址片段。
- 销售跟进过程不可见：大量电话、微信沟通沉淀在销售专用手机里，管理者难以及时判断客户意向和风险。
- 成交和履约割裂：订单、商品、课程、发货、开课、退货、售后维护没有统一链路。
- 管理干预滞后：管理者通常在结果变差后才发现问题，无法提前发现高意向未跟、客户流失、投诉风险、销售异常等信号。

### 1.3 解决方案

建设一套轻量 CRM + AI 销售管理系统：

- 通过渠道订单、线索导入、第三方销售手机数据接口，沉淀客户资产。
- 通过客户身份映射，把订单、电话、微信、课程、履约记录归并到统一客户。
- 通过 AI 分析沟通记录，生成摘要、意向、风险、建议、话术、日报周报和客户优先级。
- 通过销售工作台推动销售执行下一步动作。
- 通过管理者看板和风险中心推动主管及时干预。
- 通过订单履约能力完成一键发货、开课、退货状态同步，形成交易到维护的完整闭环。

### 1.4 成功指标

| 指标 | 试点目标 | 说明 |
|---|---:|---|
| 销售手机数据同步成功率 | >= 95% | 电话、微信、设备在线状态等 |
| 订单到客户匹配准确率 | >= 90% | 低置信度进入人工确认 |
| 高意向客户及时跟进率 | 提升 30% | 与上线前基线对比 |
| AI建议采纳率 | >= 60% | 销售或管理者确认有用 |
| 风险客户闭环处理率 | >= 80% | 有负责人、处理状态和结果 |
| 一键履约成功率 | >= 90% | 发货、开课、服务开通等 |
| 敏感数据泄露事故 | 0 | 电话、微信、聊天、录音等 |

## 2. 总体分层结构

PRD 按“四个功能层 + 一个结果层”组织。这样能保证每个功能都能说明数据来源、数据流向和业务目的。

```text
平台治理与基础配置层
  -> 组织权限 / 数据接入 / 主数据 / AI规则 / 内容激励
        ↓
轻 CRM 客户资产层
  -> 客户是谁 / 从哪里来 / 买过什么 / 谁负责 / 沟通过什么 / 当前阶段 / 下一步
        ↓
销售增长执行层
  -> 客户优先级 / AI建议 / 话术 / 跟进任务 / 成交推进 / 售后维护
        ↓
管理经营干预层
  -> 看板 / 风险 / 督导 / 分配 / 交接 / 复盘
        ↓
业务结果层
  -> 成交 / 复购 / 转介绍 / 客单价提升 / 营收增长
```

### 2.1 为什么不按“销售端 / 管理端 / 管理员端”作为一级目录

销售端、管理端、管理员端更适合做页面设计或权限说明，不适合作为 PRD 一级模块。因为同一个业务对象会被多个角色使用，例如客户、订单、AI建议、风险、任务。如果按端拆，容易重复描述，也容易丢失数据流转关系。

本 PRD 采用“业务对象 + 数据闭环”的方式拆解功能，每个模块说明：

- 数据从哪里来。
- 系统如何处理。
- 谁使用这些数据。
- 数据输出到哪里。
- 形成什么业务动作。

## 3. 用户角色

| 角色 | 核心诉求 | 主要使用能力 |
|---|---|---|
| 销售 | 每天知道先跟谁、怎么跟、为什么跟 | 今日工作台、客户详情、AI建议、话术、任务、日报周报 |
| 销售主管 / 管理者 | 看清团队过程，及时干预风险客户和异常销售 | 管理看板、风险中心、督导任务、客户分配、客户交接 |
| 管理员 / 运营 | 配系统、配规则、管数据、管权限、看同步健康 | 组织权限、数据接入、主数据、AI规则、内容激励、审计 |
| 技术 / 平台运维 | 保证数据链路稳定、权限隔离、AI任务可追踪 | 接入监控、任务队列、异常重试、日志审计、数据质量 |

## 4. 核心业务闭环

### 4.1 主数据流

```text
渠道 / 店铺 / 平台
  -> 订单 / 线索导入
  -> 商品、课程、服务映射
  -> 客户身份匹配
  -> 客户资产沉淀
  -> 销售归属
  -> 发货 / 开课 / 履约 / 退货
  -> 销售手机电话微信数据回流
  -> AI分析客户意向、风险和下一步动作
  -> 销售跟进
  -> 管理者干预
  -> 成交、复购、转介绍
  -> 新数据继续回流
```

### 4.2 关键原则

- 订单不是孤立数据，必须进入客户资产。
- 商品不是简单商品名，必须能映射到内部产品、课程、实物、服务和履约方式。
- 客户不是一条手机号记录，必须支持多身份映射。
- 销售手机是关键数据源，电话和微信数据必须能回流到客户时间线。
- AI 不直接触达客户，只给销售和管理者提供判断、建议和内容。
- 管理看板不是只看结果，而是要能推动干预动作闭环。

## 5. 模块需求

## 5.1 平台治理与基础配置层

### 5.1.1 组织权限

目标：先把系统底座搭好，保证后续客户、订单、手机、沟通记录、AI结果都有明确的数据边界和访问权限。

核心功能：

- 用户管理：销售、主管、管理员、运营、技术运维。
- 团队管理：支持部门、销售组、主管关系。
- 角色权限：不同角色看到不同数据和操作。
- 数据范围：销售看本人客户，主管看团队客户，管理员按配置查看。
- 客户交接：销售离职、调岗、冻结时，客户、任务、沟通记录、风险一并交接。
- 审计日志：客户转移、敏感数据查看、导出、配置修改必须留痕。

数据来源：

- 内部组织架构。
- 销售账号。
- 销售专用手机绑定关系。

输出结果：

- 销售和客户的归属关系。
- 管理者可见的数据范围。
- 敏感操作审计记录。

优先级：P0。

### 5.1.2 数据接入

目标：让订单、线索、手机沟通数据稳定进入系统。

核心功能：

- 渠道订单导入：支持 Excel / CSV 导入，后续预留 API。
- 渠道线索导入：支持抖店、视频号、小鹅通、百度、千川、腾讯、代发等来源标记。
- 第三方销售手机接入：通过第三方手机厂商或服务商接口获取电话、微信、录音、消息、设备状态等数据。
- 同步任务管理：记录每次导入、同步、失败、重试、部分成功。
- 数据健康看板：展示设备离线、微信同步延迟、订单导入失败、AI分析失败。
- 异常队列：客户无法匹配、商品无法映射、设备断流、订单字段缺失等进入待处理。

数据来源：

- 渠道平台导出文件。
- 第三方手机接口。
- 内部课程系统、物流系统或第三方履约接口。

输出结果：

- 原始订单快照。
- 原始沟通记录。
- 标准化订单、客户、沟通时间线。
- 数据异常处理任务。

优先级：P0。

### 5.1.3 主数据

目标：把渠道、店铺、商品、产品、课程、履约方式统一成系统可识别的数据模型。

核心功能：

- 渠道管理：抖店、视频号、小鹅通、百度、千川、腾讯、代发、其他。
- 店铺管理：每个渠道下可配置多个店铺或账号。
- 外部商品管理：平台商品、SKU、套餐、课程包。
- 内部产品管理：课程、公开课、咨询服务、实物书籍、组合包。
- 商品映射：外部商品映射到内部产品。
- 履约类型配置：实物发货、线上课开通、线下课报名、咨询服务交付、组合履约。
- 销售地址配置：每个销售可配置发货地址，用于匹配发货发件信息。

关键判断：

- “产品”和“商品”建议统一抽象为“内部产品”，商品只是渠道平台上的销售形态。
- 内部产品可以没有实物，例如线下公开课、咨询服务。
- 一个外部商品可以拆成多个履约项，例如课程 + 书籍 + 资料。
- 销管王不作为真实电商平台的上架源头，只维护映射、履约和客户经营所需数据。

数据来源：

- 平台商品导出。
- 内部课程和产品资料。
- 发货和开课规则。

输出结果：

- 订单商品可识别。
- 客户已购产品可追踪。
- 发货、开课、售后、后续推课有依据。

优先级：P0。

### 5.1.4 AI规则

目标：让 AI 判断可配置、可追踪、可人工修正。

核心功能：

- 意向等级规则：高 / 中 / 低意向，支持阈值配置。
- 风险词规则：投诉、退款、拒绝、价格异议、合规风险等。
- 跟进频率规则：不同客户阶段的超时标准。
- 客户优先级规则：意向、消费金额、最近沟通、履约状态、风险、复购机会综合排序。
- 话术规则：按产品、客户阶段、异议类型生成建议话术。
- AI结果反馈：销售或主管可标记有用、无用、需修正。

限制规则：

- AI 不允许自动打电话。
- AI 不允许自动发微信。
- AI 不允许自动承诺价格、优惠、退款、发货时间。
- AI 只能生成建议，由销售或管理者确认执行。

数据来源：

- 电话转写。
- 微信聊天记录。
- 客户资料。
- 订单和履约状态。
- 话术库、产品资料、销售规则。

输出结果：

- 客户摘要。
- 意向等级。
- 风险提示。
- 下一步建议。
- 跟进话术。
- 日报、周报。
- 客户优先级排序。

优先级：P0。

### 5.1.5 内容激励

目标：给销售提供可直接使用的内容资产，并支持后续激励、排名、分红或提成扩展。

核心功能：

- 话术库：按课程、产品、客户阶段、异议类型维护。
- 每日干货：按客户已购课程或阶段推送不同内容。
- 产品推荐素材：课程介绍、案例、优惠说明、FAQ。
- 成功案例：可供销售引用。
- 激励规则预留：成交、复购、转介绍、过程行为可作为后续激励计算依据。

数据来源：

- 运营维护内容。
- 产品资料。
- 销售优秀案例。

输出结果：

- AI话术生成可引用。
- 销售跟进客户时可快速取材。
- 后续业绩激励有基础数据。

优先级：P1，内容框架 P0 预留。

## 5.2 轻 CRM 客户资产层

### 5.2.1 客户统一身份

目标：解决订单、手机、微信、平台数据无法识别为同一个客户的问题。

核心功能：

- 客户身份字段：手机号、微信号、平台用户ID、昵称、收货人、地址片段、公司名、备注名。
- 强匹配：手机号一致、微信号一致、平台ID一致。
- 中匹配：姓名 + 地址、微信昵称 + 手机后四位、同店铺历史订单。
- 弱匹配：昵称相似、地址相似、收货人相似。
- 低置信度人工确认：不自动合并，进入候选客户队列。
- 合并与拆分：支持人工合并误拆客户，也支持拆分误合并客户。

数据来源：

- 订单字段。
- 电话号码。
- 微信联系人。
- 收货地址。
- 销售手动录入。

输出结果：

- 统一客户档案。
- 客户身份映射表。
- 客户合并候选记录。

优先级：P0。

### 5.2.2 客户归属

目标：保证同一个客户前后订单和沟通优先归属同一个销售，减少撞单和重复跟进。

核心功能：

- 已有负责人优先：历史客户再次下单，默认归属原销售。
- 新客户分配：主管手动分配，后续可扩展自动分配。
- 离职交接：销售离职时客户、任务、沟通记录、订单、风险整体转移。
- 归属冲突处理：多个销售同时关联客户时进入仲裁。
- 公海机制预留：长期无人跟进或销售离职可进入公海再分配。

数据来源：

- 客户历史负责人。
- 订单和沟通记录。
- 组织权限。
- 人员状态。

输出结果：

- 客户负责人。
- 归属变更历史。
- 客户交接任务。

优先级：P0。

### 5.2.3 客户详情

目标：销售打开客户就能知道客户是谁、买过什么、沟通过什么、下一步怎么推进。

核心功能：

- 基础信息：姓名、手机号、微信、来源、标签、负责人。
- 来源信息：渠道、店铺、订单、线索来源。
- 已购产品：课程、实物、服务、线下课、组合包。
- 消费金额：累计支付、退款、净消费。
- 履约状态：已发货、已签收、已开课、已到课、已退款。
- 沟通时间线：电话、微信、手动记录、订单、履约、AI信号。
- AI洞察：摘要、意向、风险、建议、推荐话术。
- 当前阶段：线索、已加微、需求确认、报价、成交、复购维护、流失。

数据来源：

- 客户身份映射。
- 订单。
- 履约。
- 销售手机沟通数据。
- AI分析结果。

输出结果：

- 销售跟进依据。
- 管理者干预依据。
- AI分析上下文。

优先级：P0。

## 5.3 订单与履约层

### 5.3.1 订单导入与标准化

目标：把不同渠道订单统一成系统订单，作为客户消费和履约的基础。

核心功能：

- 订单导入：支持多渠道文件导入，保留原始快照。
- 字段映射：平台订单号、店铺、商品、金额、支付状态、退款状态、收货信息。
- 商品映射：订单商品匹配内部产品和履约项。
- 客户匹配：从订单提取身份线索，匹配或创建客户。
- 异常处理：商品未映射、客户低置信度、金额异常、字段缺失。

数据来源：

- 渠道订单导出。
- 主数据配置。

输出结果：

- 标准订单。
- 客户消费记录。
- 履约任务。
- 异常处理队列。

优先级：P0。

### 5.3.2 一键发货

目标：订单中包含实物时，支持快速生成发货任务并同步物流状态。

核心功能：

- 根据订单拆分实物履约项。
- 匹配客户收货地址。
- 匹配销售发货地址。
- 生成发货单。
- 对接发货平台或导出发货文件。
- 同步物流单号和物流状态。
- 支持发货失败重试和人工处理。

数据来源：

- 订单。
- 商品履约配置。
- 客户收货地址。
- 销售发货地址。
- 物流接口或发货平台。

输出结果：

- 发货单。
- 物流状态。
- 客户详情中的履约状态。
- 售后和退货依据。

优先级：P0。

### 5.3.3 一键开课

目标：订单中包含课程时，支持快速给客户开通对应课程或报名线下课。

核心功能：

- 根据订单拆分课程履约项。
- 匹配小鹅通、内部看课网站、线下课系统。
- 创建开课任务。
- 同步开通结果。
- 支持开通失败重试和人工处理。
- 记录客户课程权益和学习状态接口预留。

数据来源：

- 订单。
- 产品课程映射。
- 第三方课程平台接口。
- 内部看课网站接口。

输出结果：

- 课程开通记录。
- 客户已购课程。
- 后续每日干货和课程推荐依据。

优先级：P0。

### 5.3.4 退货与退款

目标：退货退款影响客户状态、消费金额、销售业绩和后续维护，必须进入系统闭环。

核心功能：

- 同步渠道退款状态。
- 创建退货记录。
- 更新订单状态。
- 修正客户净消费金额。
- 影响销售业绩和后续提成口径。
- 触发客户风险提示。
- 支持售后跟进任务。

数据来源：

- 渠道退款状态。
- 物流退货状态。
- 人工售后记录。

输出结果：

- 退款 / 退货记录。
- 客户消费修正。
- 风险提示。
- 售后维护任务。

优先级：P0。

## 5.4 销售增长执行层

### 5.4.1 销售工作台

目标：销售每天打开系统后，直接看到最该处理的客户和动作。

核心功能：

- 今日优先客户：按意向、金额、风险、超时、复购机会排序。
- 高意向待跟进：AI识别或主管指定。
- 超时提醒：超过规则未跟进的客户。
- 主管指派：主管创建的督导任务。
- 下一步建议：打电话、发微信、发资料、报价、邀约、售后维护。
- 日报周报：自动汇总销售过程、客户推进、风险和成交。

数据来源：

- 客户资产。
- 沟通记录。
- AI分析。
- 管理者任务。
- 履约状态。

输出结果：

- 销售任务完成记录。
- 新沟通数据回流。
- 客户阶段变化。

优先级：P0。

### 5.4.2 AI跟进建议与话术

目标：帮助销售更快判断怎么跟客户，提高沟通质量。

核心功能：

- 客户摘要：最近发生了什么、客户关心什么。
- 意向判断：高 / 中 / 低意向和原因。
- 风险判断：断联、退款、投诉、价格异议、合规风险。
- 下一步建议：推荐具体动作。
- 话术生成：根据客户阶段、产品、异议点生成建议话术。
- 素材推荐：关联每日干货、产品资料、成功案例。

数据来源：

- 电话转写。
- 微信消息。
- 客户已购产品。
- 履约状态。
- 内容库。

输出结果：

- 销售可执行建议。
- 客户优先级。
- 管理者风险视图。

优先级：P0。

### 5.4.3 客户维护

目标：成交后继续维护客户，支持复购、转介绍和后续产品推荐。

核心功能：

- 按课程或产品推送每日干货建议。
- 根据已购产品推荐下一产品。
- 课程提醒、到课提醒、资料发送提醒。
- 售后关怀任务。
- 复购机会识别。
- 转介绍机会识别。

数据来源：

- 客户已购产品。
- 课程开通和学习状态。
- 沟通记录。
- 内容库和产品推荐规则。

输出结果：

- 维护任务。
- 产品推荐建议。
- 复购商机。

优先级：P1，基础任务 P0 预留。

## 5.5 管理经营干预层

### 5.5.1 管理者看板

目标：管理者看到团队当前销售过程，而不仅是最终业绩。

核心功能：

- 团队总览：线索、客户、跟进、成交、退款、履约。
- 高意向客户池：客户、负责人、预计金额、最近跟进、下一步。
- 漏斗诊断：线索、有效沟通、需求确认、报价、成交、复购。
- 销售过程质量：跟进频次、响应速度、有效沟通、超时客户。
- 数据健康：设备离线、同步延迟、客户未匹配、商品未映射。

数据来源：

- 客户资产。
- 订单履约。
- 手机沟通数据。
- AI分析。
- 任务状态。

输出结果：

- 管理决策。
- 督导任务。
- 销售培训和复盘依据。

优先级：P0。

### 5.5.2 风险中心

目标：提前发现会影响成交、退款、投诉或合规的问题。

核心功能：

- 高意向未跟进。
- 客户断联。
- 退款 / 投诉风险。
- 合规风险词。
- 销售承诺异常。
- 设备断流或数据缺失。
- 商品、客户、订单匹配异常。

处理动作：

- 指派销售跟进。
- 主管介入。
- 重新分配客户。
- 抽查录音或聊天。
- 标记已处理。
- 关闭风险并记录结果。

优先级：P0。

### 5.5.3 督导与交接

目标：让管理动作能够落地，而不是停留在看板。

核心功能：

- 创建督导任务。
- 指派负责人和截止时间。
- 跟踪处理状态。
- 支持客户重新分配。
- 支持销售离职交接。
- 支持交接前后客户跟进记录完整保留。

数据来源：

- 风险中心。
- 管理者手动创建。
- 组织权限和人员状态。

输出结果：

- 督导任务。
- 客户归属变更。
- 处理闭环记录。

优先级：P0。

## 5.6 业务结果层

业务结果层不作为独立页面模块，而是所有模块共同服务的最终目标。

核心指标：

- 成交金额。
- 成交客户数。
- 复购金额。
- 转介绍客户数。
- 客单价。
- 退款率。
- 销售响应速度。
- 高意向客户跟进率。
- 销售人效。

数据来源：

- 订单。
- 退款。
- 客户阶段。
- 销售任务。
- 沟通记录。
- AI判断和人工反馈。

输出结果：

- 管理复盘。
- 激励计算依据。
- 产品推荐策略优化。
- AI规则优化。

## 6. MVP 范围

### 6.1 MVP 包含

P0 必须包含：

- 组织、角色、权限、客户归属、审计日志。
- 第三方销售手机接入：电话、微信、设备状态、同步健康。
- 渠道、店铺、商品、产品、课程、履约类型主数据。
- 订单导入、订单标准化、客户身份匹配。
- 一键发货、一键开课、退货退款同步。
- 轻 CRM：客户列表、客户详情、客户时间线、已购产品、履约状态。
- AI：摘要、意向、风险、建议、话术、日报周报、客户优先级排序。
- 销售工作台：今日客户、待办、超时、主管指派。
- 管理者看板：团队总览、高意向客户、风险中心、督导任务。
- 数据异常队列：客户无法匹配、商品无法映射、设备断流、履约失败。

### 6.2 MVP 不包含

- AI 自动外呼。
- AI 自动发微信。
- 完整替代真实电商平台的商品上架。
- 完整财务结算系统。
- 复杂合同、回款、审批流。
- 完整 SaaS 商业化套餐计费。
- 面向外部租户的自助开通后台。
- 深度销售培训考试系统。

说明：多租户底层能力仍建议 P0 预留，例如核心表保留租户字段、权限隔离、配置隔离。只是内部试点阶段可以不开放外部租户运营后台。

## 7. 优先级规划

| 优先级 | 定义 | 代表功能 |
|---|---|---|
| P0 | 没有它，数据闭环或试点无法成立 | 组织权限、手机接入、主数据、订单、客户匹配、履约、AI建议、销售工作台、管理看板 |
| P1 | 价值明确，但可在试点稳定后增强 | 自动分配、内容库增强、复购推荐、漏斗诊断、排名、激励规则 |
| P2 | 商业化、规模化、精细化能力 | 租户运营后台、套餐计费、行业模板、插件化接入、客户成功看板 |

### 7.1 推荐开发顺序

1. 组织权限、租户底座预留、审计、脱敏。
2. 渠道、店铺、商品、产品、课程、履约类型主数据。
3. 第三方销售手机绑定和数据接入。
4. 订单导入、客户身份匹配、客户归属。
5. 客户详情、沟通时间线、已购产品、履约状态。
6. 一键发货、一键开课、退货退款。
7. AI摘要、意向、风险、建议、话术。
8. 销售工作台。
9. 管理者看板、风险中心、督导任务。
10. 内容库、复购推荐、漏斗诊断、激励和排名。

## 9. 非功能需求

### 9.1 安全与合规

- 手机号、微信号、聊天记录、录音、地址均属于敏感数据。
- 敏感字段按角色脱敏。
- 数据导出必须受权限控制并记录审计。
- AI分析使用的数据必须遵守租户隔离。
- 电话录音和微信记录需要明确保存周期。

### 9.2 可追溯

- AI结果必须能追溯到来源记录。
- 订单导入必须保留原始快照。
- 客户合并、拆分、转移必须留历史。
- 履约失败、同步失败必须可重试、可人工处理。

### 9.3 性能

- 销售工作台首屏 P95 响应小于 2 秒。
- 客户详情时间线 P95 响应小于 3 秒。
- 手机数据同步延迟目标小于 5 分钟。
- AI分析允许异步，目标 10 分钟内产出结果。

### 9.4 可扩展

- 接入层支持多渠道扩展。
- AI规则支持租户或业务线配置。
- 商品、课程、实物、服务通过履约类型扩展。
- 内部试点流程不能写死为唯一流程，后续对外销售时应支持行业模板。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 第三方手机接口不稳定 | AI无数据、时间线断流 | 做设备健康、同步状态、失败重试、断流告警 |
| 客户匹配错误 | 销售跟错客户、客户资产污染 | 低置信度不自动合并，进入人工确认 |
| 商品映射不完整 | 发货、开课、金额统计错误 | 未映射商品进入异常队列，补齐后重跑 |
| AI建议不准确 | 销售不信任系统 | AI结果保留来源、置信度和人工反馈 |
| 数据权限设计晚 | 后期重构成本高 | P0 建权限、脱敏、审计和租户底座 |
| 履约接口失败 | 客户体验受损 | 一键履约必须有失败重试和人工兜底 |
| 管理者只看不处理 | 管理闭环断裂 | 风险必须有负责人、状态、截止时间和关闭结果 |

## 11. 验收标准

### 11.1 数据闭环验收

- 可以从至少一个渠道导入订单。
- 订单能匹配或创建客户。
- 商品能映射到内部产品和履约项。
- 客户详情能看到订单、已购产品、履约状态。
- 销售手机电话和微信数据能回流到客户时间线。
- AI能基于客户时间线生成摘要、意向、风险和建议。
- 销售执行后，新沟通数据能再次回流。

### 11.2 履约闭环验收

- 实物订单可以生成发货任务。
- 课程订单可以生成开课任务。
- 发货和开课结果能回写客户详情。
- 退货退款能修正客户消费和订单状态。
- 履约失败进入异常队列并支持人工处理。

### 11.3 销售管理闭环验收

- 销售工作台能看到今日优先客户和下一步建议。
- 管理者能看到高意向未跟进、风险客户、数据异常。
- 管理者能创建督导任务。
- 督导任务完成后能关闭风险并保留处理记录。

## 12. 待确认问题

- 第三方销售手机服务商具体提供哪些 API：电话、录音、微信文本、语音、文件、联系人、设备状态是否都能获取。
- 微信数据采集的授权和合规边界。
- 电话录音保存周期和可查看角色。
- 小鹅通、内部看课网站、物流或发货平台的接口能力。
- 现有渠道订单导出字段样例，尤其是没有手机号时可用的身份字段。
- 商品、课程、实物、服务的主数据由哪个部门维护。
- 退款、退货、业绩和提成的最终口径。
- 内部试点是否需要先接全部渠道，还是先接 1-2 个核心渠道跑通闭环。
